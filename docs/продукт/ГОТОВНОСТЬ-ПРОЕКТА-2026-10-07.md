## 2. Как посчитали ~96%

### Шаг A — среднее пяти продуктовых контуров (как 05.10)

\[
\frac{96 + 97 + 95 + 92 + 98}{5} = 95{,}6\%
\]

### Шаг B — веса «как раньше» (API/Desktop тяжелее)

| Контур | Вес | Вклад |
|--------|-----|-------|
| Product API | 25% | \(0{,}96 × 0{,}25 = 0{,}240\) |
| Desktop | 25% | \(0{,}97 × 0{,}25 = 0{,}2425\) |
| Админка | 15% | \(0{,}95 × 0{,}15 = 0{,}1425\) |
| Mobile | 20% | \(0{,}92 × 0{,}20 = 0{,}184\) |
| Auth-стык | 15% | \(0{,}98 × 0{,}15 = 0{,}147\) |
| **Сумма** | 100% | **0{,}956 → 95{,}6%** |

### Шаг C — с docs + тестами (полная таблица 04.10)

Веса: API 20 · Desktop 20 · Admin 15 · Mobile 15 · Auth 15 · Docs 10 · Tests 5

\[
0{,}96·0{,}20 + 0{,}97·0{,}20 + 0{,}95·0{,}15 + 0{,}92·0{,}15 + 0{,}98·0{,}15 + 0{,}99·0{,}10 + 0{,}65·0{,}05 = 0{,}945
\]

→ **~94–95%**, если жёстко штрафовать неполное покрытие тестами.

### Итоговая фиксация

Для учебного MVP (критерии в [ЧТО-ЕЩЁ-СДЕЛАТЬ.md](./ЧТО-ЕЩЁ-СДЕЛАТЬ.md)) берём **продуктовое** среднее **A/B ≈ 95,6%** и округляем до:

# **~96%**

Ранее черновик «~97%» завышал Mobile (EAS ещё не сдан).  
Автотесты в итоговый «продукт %» не размывают оценку так же сильно, как в шаге C — они уже учтены внутри API (~96%) как `#85`.
